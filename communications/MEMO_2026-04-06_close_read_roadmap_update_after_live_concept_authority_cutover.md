## Purpose

Update the Close Read roadmap now that the concept-analysis family has crossed its live authority gate.

The roadmap must now avoid drifting as if the main next gap is still:

- live deployment
- basic operator visibility
- first thin-host cutover

Those were the right immediate next moves before this tranche.
They are not the right next moves now.

## Bottom Line

The roadmap has advanced one full corridor step.

What is now true:

- analyzer-v2 is live runtime authority for the admitted concept-analysis seams
- analyzer-mgmt is live enough to inspect that slice
- the-critic has a real hosted thin-client cutover for `inferential` and `logical`
- hosted logical scrutiny works against a persisted analyzer-v2-backed logical result

So the next serious roadmap step is:

- shift translated host-artifact authority out of the-critic and into analyzer-v2

That is the next move that actually makes the system more truthfully “analyzer-v2 as the brain.”

## Corrected Near-Term Corridor

### Corridor Step 1: Live authority is no longer hypothetical

The program no longer needs to speak conditionally about whether analyzer-v2 can own the admitted concept runtime live.

That proof now exists on Render.

So the next roadmap step should not reopen:

- local workflow invention
- local transformation invention
- local operator-console linkage work
- local-only cutover rehearsal

### Corridor Step 2: Reduce host-owned semantic authority further

The current live stack is improved, but not yet at the cleanest architecture.

the-critic still owns too much of the translated host-artifact path:

- strict contract normalization
- translated-result persistence/readback authority
- host-visible analysis read model

That was acceptable for this tranche.
It should not be the long-term resting place.

### Corridor Step 3: Make analyzer-v2 own translated artifacts

The next move should be:

1. have analyzer-v2 persist the translated host-contract artifact as a first-class result
2. have analyzer-v2 expose that artifact, its validation state, and provenance directly
3. make analyzer-mgmt show the raw phase outputs and the translated host artifact together
4. reduce the-critic from translator/persistence owner to launch/poll/fetch/render consumer

### Corridor Step 4: Keep the boundary narrow

The roadmap should still defer:

- new concept submodes
- cross-corpus concept thinning
- broader concept-estate migration
- broader Close Read UI work
- standalone Close Read host work
- composition-layer expansion beyond this bounded concept seam

## Roadmap Implication

The immediate Close Read concept corridor should now read:

1. live authority and thin-client cutover: complete
2. translated host-artifact authority migration into analyzer-v2: next
3. then further host thinning and future standalone Close Read extraction from a cleaner substrate

That keeps the sequencing honest:

- live runtime authority first
- artifact authority second
- broader host restructuring later

## What The Roadmap Should Avoid Next

Do not make the next serious move:

- more ad hoc the-critic translation thickening
- more host-local persistence logic
- new concept-family UI work
- new concept submodes
- broader module-composition ambition

Those are all lower priority than moving translated artifact authority into analyzer-v2.

## Updated Bottom Line

The program is now past the point where “make analyzer-v2 live for concept analysis” is the honest next step.

That has been done.

The honest next step is:

- **analyzer-v2 owns translated host artifacts**
- **analyzer-mgmt exposes those artifacts and their validation/provenance**
- **the-critic becomes a thinner read-through consumer**
