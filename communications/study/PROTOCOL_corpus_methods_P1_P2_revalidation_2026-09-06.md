## Reading and scoring order

1. Freeze SHA-256 hashes of the exact harness, definitions, design amendments, relevant execution code, protocol and all source bytes. Commit and push the freeze before generation. No design or prompt change after examining output or scores.
2. Generate the five outputs, retaining prompt/output hashes, raw outputs, step receipts, model identities, token usage, failures and cost reservations.
3. Read the outputs against the source passages. Write a substantive memo for each exact output hash: check the prior named defects, each consequential positive table cell and its cited finding/anchor, attribution, chronology, alignment qualifications and missing coverage. Report the code wall separately from semantic support. State reading limits.
4. Commit and push **all five memos before any ratings**. The harness requires each memo's bytes to match Git HEAD and records their bindings before rating.
5. Each judge sees the complete relevant sources, one output, the task and the same rubric. It sees no other score, reader memo, campaign decision, model identity or code-wall receipts. Both judges return six criterion scores and source-specific reasons. Review their reasons against the passages; do not treat scores as an automatic release threshold.

## Release and reporting

Report code-verified anchors, final IDs, declared dimensions, actual desk-ledger citation availability, and the two-key corpus wall **per output**, including failures and repairs. Report source coverage and scope/ruling limitations separately. Positive table cells must trace through existing citable findings to passages that actually support the stated actor, fact, timing and qualification. A causal/reactive status cannot move from EMA to PEACE. Reconciliation must identify object/time/qualification mismatches and preserve source answers. High scores cannot excuse a decisive error.

Release a method only after its required outputs meet the source-to-table contract. If a defect remains, leave it excluded and name it in `STUDY_corpus_methods_P1_P2_revalidation_2026-09-06.md`, FEATURES, CHANGELOG and tracker §11. Only a released method receives an entry under a new purpose group and removal of its exclusion. Preserve source files and original-study artifacts. Commit and push each phase after pull --rebase.
