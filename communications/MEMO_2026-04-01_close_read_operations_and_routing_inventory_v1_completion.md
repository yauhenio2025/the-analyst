## Purpose

Record completion of the bounded product-side companion tranche that audited real downstream operations and routing seams already embodied in current apps.

This was not a code path broadening slice.
It was a runtime-first inventory tranche meant to answer one narrower question:

- what downstream first-hop operations and adjacent artifact-routing seams are already real enough in current product code to inform later analyzer-side affordance work honestly?

It did not attempt to:

- scope `Close Read V1` as a product
- design analyzer-side affordance schema
- design analyzer attachment points
- redesign any host UX
- replace the next analyzer-side extraction tranche

## Outcome

That bounded question is now answered well enough to move forward.

The completed inventory confirms:

1. `the-critic` already contains multiple runtime-real first-hop operations over rendered analytical and research surfaces
2. those first-hop routes must be separated from destination-internal lifecycle
3. `analyzer-mgmt` is useful secondary evidence of intent and schema richness, but not runtime law
4. the right post-extraction analyzer-side target is still narrow:
   - semantic-affordance and routing-hint hypotheses for first-hop operations only

The honest closed claim remains narrow:

- we now have a runtime-first, code-backed inventory of current downstream first-hop operations, adjacent lifecycle surfaces, artifact seams, and candidate post-extraction affordance/routing hypotheses

This does not mean:

- analyzer-v2 already owns operation-family law
- a settled affordance schema exists
- `Close Read` is fully product-scoped
- host-local UX can now be generalized automatically
- aspirational downstream destinations are runtime-real

### 2. One source-of-truth matrix appendix

The reusable artifact is:

The matrix is now the durable output of this tranche.

- `operation_scope = first_hop | destination_lifecycle | intent_only`

and the stronger evidence columns:

For every `runtime_real` row, the matrix records:

### 3. First-hop routing and destination lifecycle are now documented separately

The tranche now distinguishes two different kinds of product reality:

**First-hop routing**
- user action on an analysis or research surface
- immediate artifact creation or promotion

**Destination-internal lifecycle**
- research queue / lookup / refresh
- NotebookLM-backed answer lifecycle
- outline upgrade / extract / saved-summary flows

That distinction matters because the later analyzer-side affordance work should begin only on first-hop routing, not on full destination lifecycle.

### 4. `analyzer-mgmt` is now positioned honestly

The completed memo and matrix both treat `analyzer-mgmt` as:

- secondary product-intent evidence
- schema-richness evidence

not:

- runtime proof of downstream operation law

The logic-gap prompt/schema mismatch is recorded as evidence of evolving intent, not hardened contract.

### 5. The next analyzer-side move did not change

The inventory changed the product-side picture, but not the next analyzer-side implementation step.

The next concrete code tranche remains:

- `communications/MEMO_2026-04-01_phase_e_composition_metadata_extraction_v1_scope.md`

The inventory sharpened that decision rather than replacing it:

## Strategic Implication

The strongest program update from this tranche is:

- `Close Read` is now a better-grounded flagship proving ground than before

but only in this specific sense:

- the current runtime surface already shows that rendered analysis is not enough by itself
- downstream follow-up operations and routing matter
- those operations are partly generic, partly output-specific, and partly routing-contract shaped

That strengthens the product-side case for `Close Read`, but it does not make `Close Read V1` the next implementation memo.

The next honest order remains:

1. analyzer-side composition metadata extraction
2. post-extraction analyzer-side affordance/routing addendum over first-hop operations only
3. only then a tighter `Close Read` product memo

## Honest Boundary

### What is now true

- the strongest current downstream runtime evidence is in `the-critic`
- first-hop routing is already richer than “rendered output only”
- destination lifecycle is real but should stay separate from first-hop routing
- `analyzer-mgmt` is useful for intent and schema richness, not runtime proof
- later analyzer-side affordance work now has a concrete evidence base to draw from

### What is not yet true

- analyzer-v2 does not yet attach settled affordances to composed outputs
- analyzer-side ownership of routing hints is not yet implemented
- the current matrix is not itself an analyzer contract
- `Close Read` is not yet a scoped build memo
- downstream destinations like `Book Modeler` are still aspirational unless direct runtime evidence appears
