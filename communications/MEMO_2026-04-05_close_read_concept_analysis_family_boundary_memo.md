## Purpose

Freeze the first honest `Close Read` concept-analysis family cut.

This memo is not:

- an implementation scope
- a standalone-host memo
- a claim that the whole old `ConceptsPanel` estate is ready to admit at once
- a claim that analyzer-v2 definitions already equal active runtime integration

Its job is to settle the product boundary the next implementation scope will follow:

1. exact admitted concept-analysis submodes
2. exact inherited `Close Read` baseline law
3. exact family-specific follow-up operations
4. exact legacy/analyzer-v2 seam posture
5. exact landing/detail availability rules
6. exact deferrals

## Bottom Line

`Close Read` should now admit:

- `concept analysis`

as its third serious family after:

- genealogy
- `anxiety_of_influence_thematic_single_thinker`

But that admission should be intentionally smaller than the whole old concept estate.

The first admitted concept-analysis cut is:

- `inferential`
- `logical`

with these conditions:

- it inherits the current shared `Close Read` baseline:
  - result-backed reading/work
  - provenance visibility
  - capture mode
  - `CaptureActionBar`
  - routed destinations limited to `Arsenal` and `Research todo`
- it is result-backed only
- it admits scrutiny only on the logical surface
- it keeps native concept-analysis routes live during coexistence

The first cut does **not** admit:

- concept launch/detection UI
- `assumption`
- `semantic_field`
- `causal`
- `metaphorical`
- ammunition
- `big-picture`
- `cross-concept`
- send-to-outline

## Why This Is The Right Boundary

Three things are now clear:

1. genealogy and AOI were the right first default families
2. concept analysis is the next serious family line, not “logic” in isolation
3. the first concept cut must stay small enough that it does not smuggle the whole legacy concept estate into `Close Read`

The admission audit already established the key facts:

- the old product family was concept-centered
- its runtime is split across legacy-local, external-bridge, and analyzer-v2-backed paths
- some of its most important downstream operations still live entirely in the old Critic estate

So the next honest move is not:

- UI polish
- standalone-host work
- generic composition-layer implementation
- a vague “logic family” admission

It is:

- a bounded concept-analysis family cut with explicit baseline law, explicit follow-up law, and explicit deferrals

## Decision 1: Exact Inherited Close Read Baseline

Concept analysis inherits the same umbrella baseline already admitted for genealogy and AOI.

That baseline is:

- result-backed reading/work
- provenance visibility
- capture mode
- `CaptureActionBar`
- routed destinations:
  - `Arsenal`
  - `Research todo`

This baseline applies to both admitted concept submodes:

- `inferential`
- `logical`

So the concept family is not a separate host-law experiment.
It is a family-specific extension over the same current `Close Read` operational floor.

What concept analysis adds is:

- family-specific reading surfaces
- family-specific submode tabs
- family-specific follow-up work where explicitly admitted

It does not replace the umbrella baseline with a different destination law or a different capture law.

## Decision 2: Exact Family And Submode Boundary

The first admitted concept-analysis core is:

- `inferential`
- `logical`

This is the first honest cut because:

- both are central to the old concept family’s product identity
- both align strongly with the original `Close Read` dictation around premise-testing and weak-point work
- both are stronger candidates for a serious family cut than the thinner “generic mode” tier

### Deferred submodes are split into two tiers

The first cut does **not** collapse all non-core submodes into one generic deferral bucket.

#### Deferred tier 1: external analyzer bridge

- `assumption`

This is deferred separately because its runtime seam is materially different.
It is already attached to `assumption_excavation`, but through older external analyzer plumbing rather than a clean `Close Read` family runtime.

#### Deferred tier 2: analyzer-v2-backed generic modes

- `semantic_field`
- `causal`
- `metaphorical`

These are also deferred, but for a different reason:

- they already have analyzer-v2-backed generic runtime paths
- yet they are not strong enough to define the first concept-family identity by themselves

So the first cut is:

- core = `inferential` + `logical`

not:

- all six submodes
- or a vague “some concept tools” bundle

## Decision 3: Exact Migration Truth

The governing migration fact remains a three-way split:

### 1. Legacy-local

- `inferential`
- `logical`

These are still primarily executed through old Critic-local analyzers.

### 2. External analyzer bridge

- `assumption`

This uses `assumption_excavation`, but through older external analyzer plumbing.

### 3. analyzer-v2-backed generic runtime

- `semantic_field`
- `causal`
- `metaphorical`

These already map to named analyzer-v2 concept engines.

This memo keeps one distinction explicit:

- analyzer-v2 definition existence is evidence of alignment
- it is not proof that the current active Critic runtime already uses those definitions in a clean family-native way

That matters because the first concept-family cut must not overstate migration maturity.

## Decision 4: Exact Host, Landing, And Detail Posture

Concept analysis should live under the current `Close Read` umbrella as:

- one concept-analysis landing/index
- concept detail pages beneath it

This cut is explicitly:

- result-backed only

So the first concept-family cut does **not** admit:

- concept launch UI
- type-selection UI
- detected-concept suggestions
- detected-concept generation

Those remain on native legacy concept-analysis routes during this tranche.

### Native coexistence posture

Keep native legacy routes live:

- `/p/:projectId/concept-analysis`
- `/p/:projectId/big-picture`
- `/p/:projectId/cross-concept`

This coexistence posture is intentional.
The first `Close Read` concept family cut is not a full replacement of the old concept estate.

### Landing/index inclusion law

The concept-family landing/index includes only concepts that have at least one admitted core result:

- `inferential`
- `logical`

That means:

- concepts with both core results appear
- concepts with only one core result appear
- concepts with only deferred-tier results do **not** appear
- concepts with zero admitted-submode results do **not** appear

So the first `Close Read` concept index is not a generic discovery dashboard.
It is a bounded index of concepts already usable in the first admitted concept-family cut.

Broader concept discovery remains on the native concept-analysis routes.

### Detail-page availability law

A concept detail page is admissible in `Close Read` if it has at least one admitted core result.

If both admitted core results exist:

- default active submode = `inferential`

If only one admitted core result exists:

- open that submode by default

If one admitted core submode is missing:

- render it as an unavailable tab/state
- do not silently omit it

This keeps the first cut explicit and legible:

- the family has two admitted core submodes
- but concepts may currently have only one of them available

## Decision 5: Exact Follow-Up Law

Concept analysis is the first `Close Read` family that cannot honestly remain reader-only.

But the first cut still needs a hard cap.

### Admitted follow-up in the first cut

Admitted follow-up means:

- shared `Close Read` baseline on both admitted submodes
- logical-surface scrutiny
- logical-surface vulnerability-local follow-up
- premise-level weak-point work on the logical surface

This means:

- `logical` gets the baseline plus scrutiny-local follow-up
- `inferential` gets the baseline plus its own result-backed tabs only

So scrutiny is admitted:

- only on the logical surface
- not family-wide in an undifferentiated way

### Scrutiny seam decision

For the first cut, scrutiny should be admitted by:

- wrapping the existing Critic scrutiny path under `Close Read`

not by:

- requiring a new analyzer-v2-native scrutiny contract before concept-family admission

That analyzer-v2-native scrutiny contract remains a later migration goal.
It is not a blocker for the first concept-family cut.

### Explicitly deferred follow-up and neighbors

The first cut does **not** admit:

- ammunition
- send-to-outline
- `big-picture`
- `cross-concept`

It also does not admit the broader legacy attack workflow.

So when this memo says:

- “lines of attack”

it means only:

- scrutiny-local follow-up inside the logical surface

not:

- the full downstream ammunition / export / outline workflow of the old concept estate

## Decision 6: Exact Deferrals

The following remain explicitly deferred after this boundary memo:

- `assumption` admission
- `semantic_field` admission
- `causal` admission
- `metaphorical` admission
- ammunition
- send-to-outline
- `big-picture`
- `cross-concept`
- analyzer-v2-native scrutiny contract
- composition-layer implementation
- standalone `Close Read` host

These are real future concerns.
They are simply not part of the first honest concept-family cut.
