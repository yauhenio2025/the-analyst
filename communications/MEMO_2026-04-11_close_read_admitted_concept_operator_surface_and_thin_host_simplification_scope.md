## Purpose

Define the next honest tranche after the admitted concept seam has been freshly closed live.

This tranche is not about re-proving the same corridor again.
It is about removing the remaining ambiguity around:

- where operator truth lives
- what analyzer-mgmt is responsible for showing
- what the-critic is still allowed to do on the admitted concept seam

## Bottom Line

The next bounded move should be:

1. harden and verify the already-live analyzer-mgmt job-page concept-artifact surface
2. simplify and document the already-deployed thin-host law in the-critic for admitted concept modes
3. freeze the shared authority-field law across analyzer-v2, analyzer-mgmt, and the-critic

This should stay tightly bounded to:

- `logical`
- `inferential`
- analyzer-mgmt job pages
- the-critic read-through/cache semantics

It should not reopen fresh proof work unless the implementation itself causes a regression.

## Why This Is The Right Next Corridor

The current closeout completion changed the shape of the roadmap:

- the admitted concept seam no longer needs fresh live proof to establish basic truth
- analyzer-v2 authority is already real and freshly proven
- analyzer-mgmt already has a concept-artifact job surface that works in a hydrated browser session
- the-critic already reads analyzer-v2-backed artifacts and exposes explicit authority metadata

So the honest remaining work is not "make it exist."
It is "make the operator and host responsibilities crisp."

## Strategic Reading

The larger direction remains:

- analyzer-v2 should be the analytical brain
- hosts should become thinner shells
- Close Read should become the app/product layer rather than the place where analytical truth is authored

This next tranche should therefore resist two mistakes:

1. treating analyzer-mgmt as optional or merely diagnostic
2. allowing the-critic to remain a shadow semantic author through cache behavior or legacy local paths

## Current Starting Point

### What is now complete

- fresh logical authority proof
- fresh inferential authority proof
- fresh scrutiny proof
- hydrated analyzer-mgmt browser proof for the fresh logical and inferential jobs
- the-critic read-through plus `_artifact_authority` for both admitted modes

### What is still not fully normalized

- analyzer-mgmt concept artifact display is already live, but the job page can still be hydration-laggy on fresh jobs and generic result-boundary state can still disagree with the concept-artifact truth
- the-critic still persists compatibility copies, so the law around what that cache may and may not do should be made explicit in code and docs
- legacy or dead local concept-authoring paths for admitted modes may still exist in the-critic even if the deployed happy path no longer uses them
- all three main local trees can diverge materially from deployed truth, so this tranche must start from deployed-source alignment rather than the dirty local checkouts

## Decisions To Freeze

### 1. analyzer-v2 remains the only semantic authority for admitted concept modes

For `logical` and `inferential`, analyzer-v2 is the semantic source of truth.

That means:

- no local recomposition fallback
- no local semantic mutation of analyzer-v2-backed artifacts
- no operator ambiguity about who authored the translated host artifact

### 2. analyzer-mgmt job pages are the canonical operator surface for admitted concept artifacts

For this tranche:

- job pages are the artifact/operator surface
- implementation pages remain workflow/transformation composition metadata

The operator surface should be explicit and stable enough that a fresh concept job does not feel like a generic presenter page with a hidden concept add-on.

### 3. the-critic cache is compatibility-only

The-critic may keep a local mirror for compatibility and project-scoped readback.
But that mirror should be treated as:

- non-authoritative
- analyzer-v2-derived
- metadata-preserving rather than semantically transformative

### 4. The shared authority field set should be treated as law

The following fields should be preserved consistently across analyzer-v2, analyzer-mgmt job display, and the-critic readback.
Where literal field names differ across surfaces, treat this as a semantic identity law rather than a requirement that every payload use the exact same key spelling:

- `consumer_key`
- `external_project_id`
- `analyzer_v2_job_id`
- `concept_name` / host-semantic `concept`
- `analysis_mode`
- `workflow_key`
- `engine_or_chain_key`
- `translation_template_key`
- `depth`
- `produced_at`
- `contract_validation_status`
- `lookup_mode`

The-critic-only compatibility fields may still remain host-local:

- `authority_url`
- `artifact_hash`

## Scope

- the-critic admitted-concept thin-host simplification
- explicit cache-law and authority-field normalization for admitted concept modes

## Proposed Implementation Sequence

### Phase 0: source-align to deployed truth

Before auditing or changing anything:

- fetch latest refs for `analyzer-v2`, `the-critic`, and `analyzer-mgmt`
- identify the deployed `origin/master` or other deployed source for all three repos
- work from clean isolated worktrees or deployed-source-aligned branches

Do not treat the dirty main local trees as implementation truth.
This rule applies equally to:

- `analyzer-v2`
- `the-critic`
- `analyzer-mgmt`

### Phase 1: audit the actual admitted-seam operator and host responsibilities

Inspect the live and deployed-source-aligned state of:

- analyzer-mgmt job page concept artifact rendering
- the-critic read-through and cache update path
- the-critic residual local concept translation/recomposition branches for `logical` and `inferential`

The output of this phase should be a short residual-ambiguity inventory, not another broad memo.
This phase should explicitly compare deployed behavior to the local main trees so the tranche does not rediscover already-deployed work as if it were still pending.

### Phase 2: verify and, only if needed, harden the analyzer-mgmt job page concept artifact surface

For admitted concept jobs, start by verifying the already-live `Result Boundary` concept-artifact card against the shared authority-field law and the browser proof from the completion memo.
Only harden the page if that verification shows a real remaining gap.

This phase should focus on:

- clear concept-artifact loading state
- clear concept-artifact error state
- stable rendering of the required shared authority fields
- avoiding dependence on generic presenter/result assumptions for concept artifact truth

This is not a full job-page redesign.
It is a hardening/verification slice on an already-live surface, not a build-from-scratch slice.

### Phase 3: verify, document, and clean up the-critic admitted concept seam

For admitted concept modes only:

- verify the deployed read-through semantics against source-aligned code
- remove or gate any dead local recomposition paths that are no longer part of the deployed admitted seam
- preserve project-scoped behavior through `X-Project-ID`
- make the compatibility-cache contract explicit in code and docs

If the local cache remains, it should mirror analyzer-v2 authority rather than behave like a second source of semantic truth.
This phase should be framed as dead-code cleanup plus cache-law documentation unless the audit finds a real live semantic ambiguity that still needs code change.

### Phase 4: rerun a minimal regression proof only if code changes were required

If Phases 2 or 3 change code, rerun a minimal fresh proof on one new project:

- logical
- one quick scrutiny
- inferential
- analyzer-mgmt browser check

If no code changes are required, do not reopen the full fresh-proof corridor.

## Acceptance Criteria

This tranche is complete if all of the following are true:

1. analyzer-v2 remains the sole semantic author for admitted concept artifacts
2. analyzer-mgmt job pages show the admitted concept artifact surface clearly enough that operator truth is not hidden behind generic presenter interpretation
3. the-critic admitted concept readback is explicitly non-authoritative and analyzer-v2-derived
4. no residual local recomposition path remains live for admitted concept modes, or any retained fallback is clearly dead/guarded/documented
5. the shared authority fields are consistent across analyzer-v2, analyzer-mgmt, and the-critic
6. if code changed, a bounded regression proof passes on a fresh project

## Roadmap Effect If Completed

If this tranche closes, the roadmap should be able to say:

- the admitted concept seam is both live and operationally normalized

That would make the next decision cleaner:

- either begin broader Close Read extraction / standalone shaping
- or admit the next bounded family/submode corridor

without carrying forward basic ambiguity about operator truth or host semantic responsibility.
