The catalogue (203 registered analytical engines) is being consolidated under the process shape by reading definitions, not by running everything. Codex (gpt-6-astra, xhigh) redid Sol's triage at the owner's request: keep 51 / rewrite 30 / merge 118 / retire 4, and 199 engines → 81 reader questions (`communications/study/TRIAGE_engine_catalogue_CODEX_2026-09-05.md`, `data/study/triage/families_codex.json`). Work proceeds in queues: first queue S1 A1 A2 E1 G1 P1 P2 E8 T1 (done or closing 2026-09-06), second queue G2–G4, A4–A6, C1, C6, S3, E12 plus the A3 rewrite (`CODEX_PROMPT_second_queue_2026-09-06.md`, cap $12).

The recipe: existing questions first, rewrite on demonstrated defects, validate proportionately (inventories and maps by anchor rate, rows and a source check; readings by Sonnet's six-criterion rubric with both raters independent, never head-to-head; Sol as rater gives everything 8–10 and separates nothing). `scripts/lift_engine_under_shape.py` lifts an engine's existing dimensions under the shape; the 2026-09-06 test on three engines (`STUDY_lifted_engines_2026-09-06.md`) showed lifting halves length and raises anchors but is not a quality lever, and that an engine whose dimensions are a device taxonomy (comparative_reasoning_analyzer) turns that taxonomy into the reading's categories — read the dimensions before lifting; if they name devices rather than things the text does, write questions instead.

Division of labour: Codex owns question design and corpus methods (weighty judgment); Claude owns plumbing (walls, runner, generator, desks reading the ledger by id), validation harnesses and memos. Codex runs in the same tree and commits per phase; every push redeploys the live desk, but in-flight dossier jobs survive (the old instance drains; `recover_orphaned_dossiers` resumes on startup, 24 h grace; `POST /v1/dossier/jobs/{id}/resume` on request) — a fifteen-minute analysis step does not update the job timestamp, so a frozen `updated_at` is not a stall.

**Why:** the owner said "we have like 200 engines, and i don't know if all or any of them is good" and wanted a broader strategy, then insisted the strongest model do the judging ("i don't trust sol for such an important task").
