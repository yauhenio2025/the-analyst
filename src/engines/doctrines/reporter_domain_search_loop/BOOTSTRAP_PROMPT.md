## THE CORE: the dynamic search loop (owner, 2026-09-03 — this outranks everything else in this file)
"The most important part is being able to conduct searches on Google inside the domain… the whole point is to do dynamic search where we figure out what terms represent the topic, then we start doing different combinations and we evaluate the results, then we figure out what other terms to plug based on those results, and so forth. It's an LLM-powered, context-sensitive search with us evaluating the results." Websaver's data is not the point; its loop was an early version of this. gs_revamp has the mature loop for Scholar. **Build the loop first (M1), everything else hangs off it.**

The loop, one brief:
1. **Term discovery** (LLM): from the objective + the Referee's papers (titles, abstracts) + any recall hits → the topic's vocabulary: core terms, synonyms, actors, places, named events, adjacent framings; grouped into *angles* (3–6). Record why each term is there.
2. **Lanes** = outlet × angle (site:ft.com × "warehouse strike automation"…), each lane a queue of *combinations* (term pairs/triples, quoted phrases, date windows via `tbs=cdr:`), ordered by expected yield. Budget per brief and per lane (queries, fetches, USD) enforced before spend — gs_revamp's `budgeting.py` sovereignty.
3. **Run** via the SERP transport (Oxylabs `google_search`/URL mode with `site:`; Apify once a web-SERP actor is verified); parse hits (url, title, snippet, date, outlet).
4. **Evaluate** (LLM, per hit, with the objective in context): relevant / adjacent / noise, why, which angle it serves, what it teaches — and **harvest** new terms, names, events, dates from the good hits ("this hit mentions the 2024 Amazon Coventry vote → new term").
5. **Refine** (effectors, as in gs_revamp): BROADEN (add harvested terms/angles), TIGHTEN (quote phrases, drop noisy terms), PRUNE (kill dead lanes), RE-WINDOW (shift dates when hits cluster), GO-DEEPER (page 2, related outlets). Stop rules: budget, exhaustion (adaptive: consecutive low-yield rounds), coverage (every angle has ≥N kept hits), or operator stop.
6. **Ledger**: every query, its terms, transport, cost, hit count, verdicts, harvested terms — the "truth ledger per query" — visible in the brief's console ("what we searched and why").
Then the rest of the pipeline (dedupe against recall, entitled fetch, store, Analyst, present).

## Architecture (see HUNCHES_AND_ARCHITECTURE.md for the reasoning)
One new service, **the-reporter** (FastAPI + Postgres on Render CAII; a local **fetch lane** on the owner's desktop for cookie-bearing full text), with these organs around it: Reader (stored newsletters), Syllabus corpus (historical long-form), Archivist bodies (seed), Oxylabs/Apify (fresh SERP), Analyst (analysis + diagrams), Wirecut (video), Referee/stacks/desk (callers).

Pipeline for one brief (every step recorded with receipts; skip law — an optional lane failing never kills the brief):
1. **Commission** — `POST /v1/briefs` {objective, papers[] (title/abstract/year/link), date_window, sites[] (default ft.com, economist.com, bloomberg.com, nytimes.com, wsj.com), budgets{serp_queries, fetches, usd}, sources{reader, corpus, archivist, web}, deliverables{webhook_url, secret}} → 202 {brief_id}. Idempotent on (caller, objective, window).
2. **Strategy** (LLM) — from the papers and objective: 3–6 angles, term variants per angle, which outlets/decades matter, what "already stored" should be checked first. Recorded as the brief's plan.
3. **Recall, free first** — Reader FTS (tags + term fan-out, `duplicates=hide`, full bodies), Syllabus corpus vector search (embed the angles; filter by publisher/date; pull fulltext by `string_agg(chunk)`), Archivist `articles` FTS. Dedupe by canonical URL + normalized headline. Everything found becomes `known_items` so paid search does not re-buy it.
4. **Fresh search, metered** — per outlet `site:` queries with `tbs=cdr:` windows through the existing Oxylabs URL-mode client (Apify as a second transport once a web-SERP actor is verified); LLM slate judgment (keep/drop with reasons); query-budget ledger like gs_revamp.
5. **Fetch, entitlement-aware** — enqueue bodies; the desktop fetch lane (Archivist daemon ladder: web-auth provider → cookie profile → httpx) fetches what the owner is entitled to; paywalled teasers are parked, never stored as bodies; PDFs to S3 later.
6. **Store + catalog** — `articles` with `search_vector`, per-brief `brief_items` (source lane, why kept, entitlement state).
7. **Analyse** — build one headed bundle (owner's stacks header shape) from the kept full texts + the papers' abstracts; `POST /v1/dossier/exemplars` then `POST /v1/dossier/jobs` on The Analyst with `entry: use` and the objective as intent (audience from the caller); poll or subscribe to its SSE; the dossier (text, anchored tables, diagrams, PDF) is the brief's analytical body.
8. **Present + deliver** — a brief page (sources by lane, what was found/parked/skipped, the dossier inline, receipts) in a **briefs library** front end (copy the Analyst desk shell: dark editorial, `router.ts`, `tokens.css`); webhook the caller (`X-Reporter-Signature`) with the brief URL; optional Wirecut film.

## Rules
- **Secrets:** `.secrets/` and `.env` are git-ignored; never print values; env-var NAMES only in docs. The Syllabus DB user is production master — read-only sessions, SELECT only, `PGCONNECT_TIMEOUT=20`.
- **Do not touch** the `gsi` Render workspace (client production) or The Analyst's pipeline internals; call its API.
- **LLM-first:** strategy, slate judgment, entitlement reasoning and composition are model calls with recorded prompts/responses; code only sequences, counts, dedupes and records. Every call receipted (model, tokens, cost, hash).
- **Budgets:** per-brief query/fetch/USD caps, enforced before spend; free recall before paid search.
- **Honesty:** the brief states what was searched, found, parked (paywalled), skipped and why; stored full text is never a teaser.
- **Verify like the owner does:** Playwright walk of every UI change; one live brief end-to-end before calling a milestone done; commit and push at every milestone (sessions can be cut off).
- Follow the global CLAUDE.md conventions: docs/FEATURES.md + CHANGELOG.md, communications/IMPLEMENTATION_TRACKER.md and BUG_TRACKING.md, `start` script, checkpoint/resume, aggressive logging.
